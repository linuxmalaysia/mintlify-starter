Elastic Stack on Podman is an open-source automated deployment toolkit that installs and configures Elasticsearch 9.4.4, Kibana 9.4.4, and Fleet Server as rootless Podman containers on Linux-based systems. Rather than manually pulling images, writing compose files, and managing TLS certificates, you run a single shell script — or a set of Ansible playbooks — and the toolkit handles every step: image verification, credential generation, certificate distribution, and service startup. At the heart of the project is a commitment to security: every component runs from a **distroless Wolfi base image**, which strips out the unnecessary OS packages that traditional images carry, dramatically shrinking the attack surface of each container.

## Deployment options

Choose the topology that matches your environment. All options are driven by the same codebase — you select your target by setting the `deployment_option` variable in `ansible/group_vars/all.yml` or by following the appropriate guide.

| Option | Environment | Topology | Best for |
|--------|-------------|----------|----------|
| **WSL2** | Windows 11 with WSL2 | Minimum 3 Podman nodes/pods | Local development and testing on Windows |
| **Single Node** | Single physical host or VM | 3 Podman pods on one machine | Developer workstations and small labs |
| **Multi-Node VM** | Multiple VMs or bare-metal hosts | Dedicated Podman node per VM | Staging and pre-production environments |
| **3-Node Cluster** | Three dedicated hosts | One Elasticsearch node per host | Production-like high-availability testing |

## What you get after setup

Once the setup scripts or Ansible playbooks complete successfully, you have a fully operational Elastic Stack with TLS-secured inter-service communication and auto-generated credentials:

- **Elasticsearch** is available at `https://localhost:9200` — secured with a self-signed CA certificate saved to `elk-wolfi/certs/http_ca.crt`.
- **Kibana** is available at `http://localhost:5601` — pre-enrolled against your Elasticsearch instance using the generated enrollment token.
- **Fleet Server** is available at `https://localhost:8220` — ready to accept Elastic Agent enrollments once you configure a service token and policy ID.

Your auto-generated `elastic` user password and Kibana enrollment token are both written to `elk-wolfi/temp_credentials.txt` immediately after Elasticsearch starts.

<Note>
  Store the contents of `elk-wolfi/temp_credentials.txt` somewhere secure and remove the file from the repository directory once you have recorded the credentials. The file is listed in `.gitignore` by default, but treat its contents as sensitive.
</Note>
